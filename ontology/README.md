# Stefan Zweig Digital Estate Ontology (SZDO)

Formal OWL ontology for the digital estate (Nachlass) of Stefan Zweig.

- Namespace `https://gams.uni-graz.at/o:szd.ontology#`, prefix `szdo:`
- Version 2.0.0, English identifiers, bilingual (de/en) labels and definitions
- Licence CC BY 4.0
- Live documentation at https://chpollin.github.io/SZD/ontology/

## Versions

| Version | Location | Change |
|---------|----------|--------|
| v0.x | GAMS (stefanzweig.digital) | Implicit in `szd-TORDF.xsl` of the presentation layer, English camelCase terms, in production |
| v1.0.0 | this repository | Formal OWL ontology with German identifiers and a compatibility layer for the GAMS terms |
| v1.1.0 | this repository | Date evidence, agent role hierarchy, RiC-O alignments, Klawiter corrections |
| v1.2.0 | this repository | Two layers, generic `nachlass:` ontology imported by `szdo:` |
| v2.0.0 | this repository | English identifiers only. Where the GAMS vocabulary already has an English term with the same meaning, that term is canonical, so live GAMS data conforms without a mapping layer. GAMS terms with a different meaning stay as `owl:deprecated` in PART 10 of `szd-ontology.ttl`. The German v1.2.0 identifiers are dropped, [migration-v2.csv](migration-v2.csv) maps them to the new ones. `nachlass:` moves to 0.2.0 with the same renaming. |

## Two layers

- `nachlass-ontology.ttl` (`https://w3id.org/nachlass#`) is the generic core for any estate project.
- `szd-ontology.ttl` (`https://gams.uni-graz.at/o:szd.ontology#`) specialises it for Stefan Zweig Digital and imports it via `owl:imports`.

## Files

| File | Content |
|------|---------|
| `nachlass-ontology.ttl` | Generic estate ontology |
| `szd-ontology.ttl` | SZD ontology with GAMS PIDs, Klawiter integration and the legacy GAMS terms |
| `szd-shapes.ttl` | SHACL shapes, including the ASCII naming convention |
| `sample-instances.ttl` | Sample instances generated by `scripts/generate_instances.py` |
| `reconciliation.ttl` | Klawiter links generated by `scripts/reconcile_klawiter.py` |
| `migration-v2.csv` | Mapping of every retired `szdo:` v1.2.0 and `nachlass:` 0.1.0 identifier to its v2.0.0 successor |
| `validate.py` | Six-stage validation (syntax, metrics, SHACL including the sample instances, OWL checks including the guard against retired identifiers, OntoClean, competency questions) |
| `generate_docs.py` | Builds the HTML documentation in `../docs/ontology/` |

## Foundations

- Records in Contexts (RiC-O) for the archival structure (estate, collection, record, instantiation)
- IFLA Library Reference Model (LRM) for the work layer (work, expression, manifestation, item)
- CIDOC Conceptual Reference Model (CRM) for events, provenance and biography

## Usage

```bash
python ontology/validate.py
python ontology/generate_docs.py
python -m http.server -d docs 8000   # http://localhost:8000/ontology/
```

## Class overview

```
szdo:Estate (fonds)
├── szdo:Collection (works, correspondence, autographs, library, ...)
│   └── szdo:Record (Manuscript, Typescript, Book, Autograph, ...)
│       └── szdo:DigitalObject (METS, IIIF, facsimile)
│
szdo:WorkIndexEntry (work index SZDWRK)
├── szdo:Expression (translation, adaptation)
├── szdo:Manifestation (published edition, Klawiter)
└── szdo:SecondaryLiterature (Klawiter)
│
szdo:Agent: szdo:Person, szdo:Organisation (SZDPER, SZDORG)
szdo:BiographicalEvent (life calendar SZDBIO)
szdo:Place: szdo:GeographicalPlace, szdo:Location (SZDSTA), szdo:PlaceOfOrigin
szdo:ProvenanceEvent, szdo:ProvenanceFeatureInstance
```
